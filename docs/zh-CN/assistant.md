# Windows 图形升级助手：从这里开始

**版本：0.1.0 Alpha。已通过离线测试及打包启动自检，尚未完成这个新工具的真机端到端验收。**
它适合受控试验；请不要把“代码能运行”理解为“已经在所有 1.0 TEST 机器验证成功”。

[下载 Windows 64 位程序](https://github.com/1977899016-cell/zune30-research/raw/refs/heads/main/downloads/ZZAudio-Zune30-Assistant-v0.1.0-alpha.1-win64.zip) · [English](../en/assistant.md)

## 你只需要认识这几个按钮

| 按钮 | 做什么 |
| --- | --- |
| 检查连接 | 读取设备身份、版本，判断能否继续。不会安装程序。 |
| 开始 / 继续备份 | 自动分两轮读取原系统、完整 NOR 和硬盘前部，保存到电脑。设备会重启。 |
| 恢复原系统 / 首次恢复验证 | 引导你进入恢复画面，然后只写回这台机器的原始 NK。 |
| 选择固件 / 升级 | 选择你已有的官方 3.3 NK/CAB，自动构建本机镜像；完成后再确认安装。 |
| 打开私有备份 | 打开本机备份文件夹；建议再复制一份到另一块硬盘。 |

## 使用前准备

1. 使用 Windows 64 位电脑，已安装能识别旧 Zune 的驱动。程序本身不要求安装 Python。
2. 暂时只连接一台 Zune，保持足够电量和可靠的 USB 连接。
3. 等官方 Zune 软件的更新/同步结束，再退出它，避免两个程序争用 USB。
4. 准备自己的第一代 30G、1.0 (186) TEST 机器，以及自己已有的官方 3.30.39 NK 或包含它的 CAB。
5. 把下载 ZIP 解压到普通本地文件夹，双击 `ZZAudio-Zune30-Assistant.exe`。

工具不包含微软固件，不会从不明站点自动下载固件。
首次运行不会自动连接或写入设备；必须先点“检查连接”。

## 第一步：检查连接

点击“检查连接”。正常时会显示固件版本和设备身份末尾几位。

- 如果是已分析的 `01.00.00186.00-02.04`，可以继续受控备份。
- 其他版本、其他型号或同时连接多台设备时，工具会限制写入。
- 仅显示“1.0 TEST”还不足以确认整个构建匹配。取回原 NK 后还会检查其实际摘要；
  再取回 NOR 后还会检查启动器构建。不匹配就保存备份并停止升级。

勾选实验版说明后，才会开放符合条件的写入按钮。

## 第二步：备份原机

点击“开始 / 继续备份”，先阅读确认框。

**USB 备份需要替换旧测试入口 `qtk.exe` 并重启；这个旧程序本身无法通过该接口先备份。**
因此这不是零改动的备份。确认后，工具只向自己创建并完整校验的容器写入备份结果；
系统文件、NOR 和硬盘前部作为只读来源。

工具先备份 NK，再核对实际构建，之后才允许读取闪存和硬盘前部。
不要在备份时拔线、关闭程序或手动启动 Games。

完成后会保存：

```text
nk.original.PRIVATE.bin          原系统
nor.original.PRIVATE.bin         完整 2 MiB NOR
disk-prefix.original.PRIVATE.bin 前 1 MiB 硬盘数据
vault.legacy.PRIVATE.bin         原机旧安全数据
backup-inventory.PRIVATE.json    大小、摘要与一致性校验
```

默认位置为：

```text
%LOCALAPPDATA%\ZZAudio\ZuneAssistant\Backups\
```

不需要手动拼路径，点“打开私有备份”即可。
目录里的原始容器和操作日志也应保留。不要把整个目录上传到 GitHub 或发到群里。

## 首次升级前：验证恢复可用

备份完成后，先点“恢复原系统 / 首次恢复验证”。窗口会逐步提示按键：

1. 保持 USB 连接，HOLD 解锁。
2. 按住“返回”，短按“播放”后松开播放，继续按返回约 20 秒。
3. 出现黄色 Pyxis maintenance 后，松开所有键。
4. 只短按一次返回，进入提示连接电脑恢复固件的画面。
5. 在工具的引导框中点击“确定”，写回自己的原始 NK。

**不要点恢复出厂、格式化或初始化磁盘，不要改 SIG。**
恢复回 1.0 并检测到正常接口后，工具才开放首次升级。
恢复接口不提供完整的暂存文件回读，因此工具会如实记录“完整传输确认”，不会声称已经回读了全部文件。
还需要你看一眼设备是否真的进入正常菜单。

## 第三步：选择固件并确认升级

1. 点“选择固件 / 升级”，选择已有的官方 3.30.39 NK 或 CAB。
2. 工具自动核对版本指纹、使用本机备份构建兼容镜像，过程中只写电脑本地文件。
3. 提示构建完成后，再点“确认并安装升级”。
4. 阅读本次安装确认，确认后保持连接等待。

生成的系统包含本机开机 RAM 兼容处理，属于**基于官方 3.3 的定制研究版**，不是完全未修改的原版。
本工具不自动安装中文或 FLAC 功能，那是仓库中另外的适配工作。

正常接口的暂存文件会完整分段回读，队列和身份再检查通过后才提交。
每次安装事务只提交一次；提交后 USB 断开不会触发自动重刷。

电脑检测到 3.3 接口后，仍请分别确认：正常菜单、“关于”版本、真实重启，以及官方 Zune 软件识别。
工具不会把版本字符串当成这些项目全部通过。

## 如果黑屏怎么办

点“恢复原系统”，按引导手动进入连接电脑恢复画面，再确认还原。
它会使用同一台机器已经校验的原 NK。

**黑屏后的按键通常仍需要人操作，工具不能保证无人值守恢复。**
恢复是否成功要看设备是否进入正常菜单。若上一轮恢复结果仍未确定，工具会禁止再次提交，
请先检查屏幕、连接状态和本地日志；不要为解除限制删除事务日志。

## 常见情况

| 情况 | 处理 |
| --- | --- |
| 检测不到设备 | 检查 USB、设备电量和旧 Zune 驱动；不要同时连接多台。 |
| 按钮是灰色 | 先检查连接；写入还需要勾选实验版说明，升级需要完整备份和恢复验证。 |
| 提示构建不匹配 | 这台机器不属于当前严格支持范围。不要改源码中的摘要强行通过。 |
| 提示未知固件队列 | 已停止，未追加提交。保留日志，先确认之前的传输和设备状态。 |
| 提交后暂时断线 | 等设备启动。不要连续点击升级或恢复。 |
| 提示备份不完整 | 不会开放升级；保留容器和日志继续诊断。 |
| 等待超时 | 工具不会盲目重复提交。查看屏幕，必要时按恢复引导操作。 |

## 这版已经验证到哪里

- 43 项离线测试通过，包括实际 ARM 备份程序在模拟 CE API 下的执行。
- 覆盖换机、备份被改动、错误队列、暂存损坏、提交后断线和禁止重复提交等情况。
